# Third-party notes

The only external Rust dependencies are the `objc2` family of crates, which `nxkit-metal` uses to bind Metal on macOS. They are Zlib OR Apache-2.0 OR MIT. `deps.toml` lists them with their pinned commit. `Cargo.lock` lists the other crates of the workspace only.
On macOS, `nxb-sys` links the system zlib (`/usr/lib/libz`) dynamically. The shader translator front end is a Rust port of the Ryujinx
shader translator, see below. The other third-party material is the rewrite rule data below.

## Formats and algorithms written from public documentation

The code was written from public specifications, public documentation, or observation of the output of tools. No code was
taken from other implementations.

| area | where | basis |
|---|---|---|
| Mach-O code signature (SuperBlob, CodeDirectory, requirements, entitlements, `CodeResources`) | `nxb-pack` | output of Apple `codesign` on test bundles, and public headers |
| metallib container and AIR conventions | `air-bc`, `air-emit`, `air-lib` | observation of the output of Apple tools. No Apple code is copied |
| LLVM 14 bitcode | `air-bc` | the public LLVM bitcode documentation |
| NCA, NSP (PFS0), IVFC, BKTR, RomFS, NSO, NACP, SARC, BNSH, BAHS, Yaz0 | `nxb-extract`, `nxb-split`, `nxb-romfs`, `nxb-hos`, `nxb-rewrite` | public format documentation of the homebrew community. The `prod.keys` text format is the common `name = hex` layout |
| zstd decoder | `nxb-split`, `nxb-codec` | RFC 8878 |
| LZ4 block decoder | `nxb-codec`, `nxb-split` | the public LZ4 block format description |
| AES-128 (ECB, CTR, XTS with the console tweak) | `nxb-extract`, `nxb-sys` | FIPS 197, NIST SP 800-38A, IEEE 1619. The test vectors are the published ones |
| SHA-1, SHA-256 | `nxb-model`, `nxb-sys` | FIPS 180-4. The test vectors are the published ones |
| AArch64 decoding and patching | `nxb-a64`, `nxb-rewrite` | the Arm Architecture Reference Manual |
| Property lists (XML and binary) | `nxb-plist`, `nxb-pack` | public Apple documentation and observed output |
| Block-linear texture layout (mip block height, layer stride) | `nxkit-metal` | the layout rules of deko3d (`dk_image.cpp`) as used in nxnative. The code is written anew and no source is copied |

## Runtime services ported from nxnative

The `offline` service of `nxkit-rt` (`crates/nxkit-rt/src/offline/`) is a Rust port of the entries of `dm/host/hle_offline.c`
and `dm/host/hle_net.c` of the nxnative engine that need no state of the host. The nxnative engine is published under the MIT
licence, Copyright (c) 2026 seedds. The full notice is in the section "Rewrite rules from nxnative" above.

The crate `nxkit-hos` follows `dm/host/hle_thread.c` and the svc handlers for ArbitrateLock, ArbitrateUnlock, WaitProcessWideKeyAtomic,
SignalProcessWideKey, WaitForAddress, SignalToAddress and the events. It ports the lock handoff, the condition variable key rules and the
address arbitration arithmetic. It does not copy the global lock. It uses the same licence notice as above.

The crate `nxkit-svc-system` (`crates/nxkit-svc-system/`) takes values and data from the nxnative engine. It uses the same licence
notice as above. The command IDs and layouts of the services are from libnx (ISC licence, `switch/services/*.c` and `*.h`) and from the
switchbrew wiki, and no code is copied from them.

| nxkit file | nxnative source |
|---|---|

The crate `nxkit-nvn` (`crates/nxkit-nvn/`) ports logic and data from the nxnative engine. The nxnative engine is published under the MIT
licence, Copyright (c) 2026 seedds. The full notice is in the section "Rewrite rules from nxnative" above.
